# Для следующей сборки приложения

Backend уже готов к этим изменениям, старое приложение продолжает работать.
Сервер для проверки — тест: `https://birchat-backend-staging.onrender.com` (код входа — у руководителя проекта).

## 1. Файлы: загрузка напрямую и показ внутри приложения

Подробно — [flutter-files.md](flutter-files.md): загрузка в 3 шага (`upload-url` → `PUT` → `complete`), ссылки на вложения экрана одним запросом (`download-urls`), фото/голосовые/видео внутри приложения, а не в браузере.

## 2. Диалог с AI

Уже работает без изменений в приложении: `GET /ai/history` отдаёт **только сегодняшний** диалог (с полуночи по Алматы).

### Новые вопросы сверху

```http
GET /api/companies/{companyId}/ai/history?order=newest&limit=50
Authorization: Bearer {accessToken}
```

`messages` идут так: последний вопрос, ответ на него, предыдущий вопрос, ответ на него… То есть показывать список как есть, сверху вниз.

После нового вопроса (`POST /ai/ask`) вставлять пару «вопрос + ответ» **в начало** списка, а не в конец.

### Кнопка «Новый диалог»

```http
POST /api/companies/{companyId}/ai/history/clear
Authorization: Bearer {accessToken}
```

Ответ `204`. Удаляет вопросы и ответы пользователя в этой компании — после этого `history` пустой. Перед удалением стоит спросить подтверждение.

## 3. Сообщения, группы, компания (backend v1.5)

### Удалить сообщение у всех

```http
DELETE /api/companies/{companyId}/chats/{chatId}/messages/{messageId}
```

`204`. Может **автор** сообщения или **директор**; остальным — `403 FORBIDDEN`. Повторное удаление — тоже `204`.
Сообщение пропадает из `GET …/messages`, поиска и AI.

Чтобы убрать удалённое с экрана у остальных (пока работает polling), вместе с опросом новых сообщений спрашивайте:

```http
GET /api/companies/{companyId}/chats/{chatId}/messages/deleted?since=2026-11-15T10:00:00Z
```

```json
{ "messageIds": ["…"], "checkedAt": "2026-11-15T10:00:05.123Z" }
```

Уберите эти сообщения с экрана и сохраните `checkedAt` — это `since` для следующего запроса. `+` в дате в URL кодируйте как `%2B` или используйте `Z`.

**При открытии чата** вызовите запрос **без `since`**: вернётся пустой список и `checkedAt` — серверное время. Не подставляйте в `since` время телефона: часы телефона могут спешить, и удаление потеряется (проверено на тесте: расхождение в 2 секунды уже прятало удаление).

### Кто прочитал сообщение

```http
GET /api/companies/{companyId}/chats/{chatId}/messages/{messageId}/readers
```

```json
{
  "messageId": "…",
  "readCount": 2,
  "recipientsCount": 5,
  "readers": [
    { "userId": "…", "displayName": "Нурлан", "initials": "Н", "avatarUrl": null, "lastReadAt": "2026-11-15T10:02:11Z" }
  ]
}
```

Автор в списке не учитывается. `lastReadAt` — когда человек последний раз отмечал чат прочитанным (не обязательно момент прочтения именно этого сообщения). Доступно любому участнику чата. Прочтение считается по `POST …/read` — вызывайте его, как сейчас.

### Переименовать группу

```http
PATCH /api/companies/{companyId}/chats/{chatId}
{ "name": "Склад Актобе" }
```

Только директор, только группа (общий чат — `400 VALIDATION`). Ответ — карточка чата, как у `GET …/chats/{chatId}`.

### Удалить компанию

```http
DELETE /api/companies/{companyId}
```

`204`, только директор. Компания пропадает из `GET /companies/my` у всех сотрудников; любые запросы к ней дальше дают `403 NOT_A_MEMBER` — по этой ошибке приложение должно вернуть пользователя к списку компаний. Перед удалением обязательно подтверждение (действие для всех сотрудников). Данные на сервере сохраняются, восстановление — через поддержку.

## 4. Push-уведомления (APNs)

Сделано по ТЗ приложения. Отличия от ТЗ — в конце раздела.

### Регистрация устройства

```http
POST /api/devices
Authorization: Bearer {accessToken}
{ "platform": "IOS", "token": "<APNs device token, hex>", "environment": "production", "locale": "ru" }
```

`204`. `environment`: `sandbox` для сборок из Xcode, `production` для TestFlight и App Store. `locale`: `ru` или `kk` (по умолчанию `ru`). Повторная регистрация того же токена обновляет язык, окружение и владельца. Вызывайте при каждом запуске и после входа.

```http
DELETE /api/devices/{token}
```

`204`, при выходе из аккаунта (до `POST /auth/logout`, пока жив access-токен). Неизвестный токен — тоже `204`.

### Уведомление

```json
{
  "aps": {
    "alert": { "title": "Nomad Trade", "subtitle": "Склад Актобе", "body": "Нурлан: По оплате ждём подтверждение до пятницы" },
    "badge": 7, "sound": "default", "thread-id": "<chatId>"
  },
  "companyId": "…", "chatId": "…", "messageId": "…"
}
```

* Приходит всем участникам чата, кроме автора и тех, у кого этот чат открыт (запрос сообщений чата был меньше 15 секунд назад).
* `subtitle` — только у групп. `body` — «Имя: текст» до 100 символов; строка ответа `> …` и пересылки `>> …` убирается; вложения: `📎 имя файла`, `📷 Фото` / `📷 Фотосурет`, `🎤 Голосовое сообщение` / `🎤 Дауыстық хабарлама`.
* `badge` — непрочитанные по всем чатам и компаниям получателя.

### Отличия от ТЗ

* `POST /api/auth/logout` **не удаляет** устройства: сервер по refresh-токену не знает, с какого устройства выход, и удалил бы пуши на втором телефоне пользователя. Удаляйте своё устройство через `DELETE /api/devices/{token}`. При удалении аккаунта (`DELETE /api/users/me`) устройства удаляются на сервере.
* Тихий пуш с новым `badge` после `POST …/read` пока не сделан (в ТЗ — «не срочно»). Приложению стоит самому обновлять бейдж после прочтения.

## 5. Realtime по WebSocket (вместо опроса раз в 5 секунд)

Опрос (`GET …/messages?after=`) продолжает работать — WebSocket можно включать постепенно и оставлять опрос запасным вариантом (например, раз в 30–60 секунд и после переподключения).

### Подключение

```text
wss://birchat-backend-staging.onrender.com/ws      (тест)
wss://birchat-backend.onrender.com/ws              (прод)
```

1. Открыть соединение (без токена в адресе и заголовках).
2. В течение 10 секунд отправить: `{"type":"auth","accessToken":"<access token>"}`.
3. Сервер ответит `{"type":"auth.ok","userId":"…","expiresAt":"2026-11-15T17:15:00Z"}`.

Сервер **закрывает соединение с кодом `4401`**, если токен неверный или когда он истёк (`expiresAt`). Приложение обновляет токен (`/auth/refresh`) и подключается заново. При любом обрыве — переподключаться с нарастающей паузой (1, 2, 5, 10 с) и после подключения дозапрашивать пропущенное обычным `GET …/messages?after=<последнее сообщение>` и `GET …/messages/deleted?since=…`.

Сервер шлёт WebSocket ping каждые 25 секунд (библиотеки отвечают сами). По желанию: `{"type":"ping"}` → `{"type":"pong"}`.

### Пока чат открыт

Раз в ~10 секунд отправлять `{"type":"viewing","chatId":"…"}` — тогда пользователю не придёт push о сообщениях этого чата (замена правила «опрашивал чат меньше 15 секунд назад»).

### События от сервера

У каждого события есть `type`, `companyId`, `chatId`. Приходят всем участникам чата, **включая автора** (на его другие устройства) — дубликаты отсекайте по `message.id`.

```json
{ "type": "message.created", "companyId": "…", "chatId": "…",
  "message": { "id": "…", "userId": "…", "authorName": "Нурлан", "authorInitials": "Н", "type": "TEXT",
               "text": "…", "createdAt": "2026-11-15T17:00:00Z", "attachments": [] } }

{ "type": "message.deleted", "companyId": "…", "chatId": "…", "messageId": "…" }

{ "type": "chat.read", "companyId": "…", "chatId": "…", "userId": "…",
  "lastReadMessageId": "…", "lastReadMessageCreatedAt": "2026-11-15T17:00:05Z" }

{ "type": "chat.renamed", "companyId": "…", "chatId": "…", "name": "Склад Актобе" }
```

`message` — тот же объект, что в `GET …/messages`. `chat.read` — кто-то отметил чат прочитанным: можно обновлять галочки «прочитано» без запроса `readers`. Неизвестные `type` игнорируйте — события будут добавляться.
