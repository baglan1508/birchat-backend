# Выпуск 07: полнотекстовый поиск по сообщениям

Ветка: `feature/full-text-search` → `develop` (тест) → `main` (прод)
Пункт плана: №7 (см. [README](README.md))

## Проблемы

1. **Нет морфологии.** Поиск шёл подстрокой: «договоры» не находил «договора», «договором», «накладные» — «накладную».
2. **Нет индекса.** Каждый поиск читал все сообщения компании и проверял каждое (`LOWER` + `LOCATE`). Чем больше переписка, тем медленнее.

## Что изменилось

### База (миграция V16)

* Функция `birchat.search_text(text)`: знаки препинания → пробелы, чтобы номера, телефоны, даты и коды делились на слова одинаково в тексте и в запросе.
* Колонка `chat_messages.search_vector` — поисковый вектор текста с русской морфологией (`to_tsvector('russian', …)`). Считается самой базой при вставке и изменении сообщения, для старых сообщений — при миграции.
* GIN-индекс `idx_chat_messages_search_vector`.

### Поиск

* Сообщения ищутся по индексу: слова приводятся к основе («договоры» → «договор»), `ё` = `е`.
* В сообщении должны встретиться **все слова** запроса, порядок не важен.
* **Последнее слово** ищется как начало слова: «догов» уже находит «договор» — удобно, пока пользователь печатает.
* Номера и коды: «INV-2024-15», «2024», «123-45-67», «10.11.2026» находят сообщения с ними.
* Права доступа те же: общий чат, группы, где пользователь участник; директор — все чаты.
* Запрос из одних знаков («!!») в индекс не отправляется.
* Поиск по **именам файлов** не менялся (подстрока).

### API

Без изменений: `GET /api/companies/{companyId}/search?query=…&limit=…`, тот же ответ. Приложению ничего менять не нужно.

## Что стало иначе для пользователя

| Запрос | Было | Стало |
|---|---|---|
| «договоры» при тексте «подписали договора» | не находит | находит |
| «счет» при тексте «счёт» | не находит | находит |
| «догов» | находит (подстрока) | находит (начало слова) |
| «говор» (середина слова) | находит | **не находит** |
| «договор аренды» при тексте «аренда по договору» | не находит | находит |
| «не», «по», «за» (служебные слова) | находит почти всё подряд | ничего не находит |

Поиск по середине слова потерян сознательно: так работает поиск в мессенджерах, а индекс по части слова — отдельная тяжёлая структура.

Казахский язык: отдельного словаря в Postgres нет. Слова находятся по точной форме и по началу слова («кітап» находит «кітаптарды»), но без полной морфологии.

## Проверено до выпуска

Локально на PostgreSQL 16: миграции V1–V16, затем 200 000 сообщений в 50 компаниях.

* Старые сообщения получили вектор при миграции, отредактированные пересчитываются.
* Права: сотрудник вне группы не находит сообщения группы; удалённые сообщения не находятся.
* Индекс используется и при подстановке значений, и в «общем» плане запроса (как его готовит JDBC-драйвер после 5 вызовов).
* Редкое слово в компании на 4 000 сообщений: **1 мс** вместо **10 мс** при старом поиске. Время старого поиска растёт с размером переписки, нового — почти нет.
* Частое слово (есть в трети всех сообщений): ~11 мс. Если переписка вырастет на порядки, следующий шаг — составной индекс по компании и тексту (расширение `btree_gin`).
* Спецсимволы в запросе (`' & | ! ( ) : *`) не ломают запрос.

## Тесты

`SearchServiceTest`: порядок результатов как в индексе; запрос без букв и цифр не идёт в индекс; лимит ограничивается до 50 перед поиском; права (сотрудник/директор) передаются в запрос.

## Откат

Rollback деплоя на Render. Колонка `search_vector`, функция и индекс останутся — старый код их не читает. Вставка сообщений работает (колонку считает база).
