# Выпуск 2026-11-10-05: тестовое окружение (staging)

Ветка: `feature/staging-env`
Пункт плана: №5 (см. [README](README.md))

## Проблема

Был только прод. Любое изменение проверялось сразу на реальных пользователях, а тестовые данные смешивались с настоящими.

## Решение

Отдельное тестовое окружение со своим сервером Render, своей базой и своим хранилищем файлов. Описание обоих окружений, поток веток и полный список переменных — в [docs/environments.md](../environments.md).

* Тест: Render `birchat-backend-staging` (Starter, Frankfurt), ветка `develop`.
* База: бета-проект Neon (`birchat_beta`). Её схема совместима с продом, миграции V12–V14 докатятся при первом запуске.
* Файлы: bucket `birchat-beta-files`.
* Новый порядок: PR → `develop` → проверка на тесте → PR `develop` → `main` → прод.

## Изменения в коде

* `GET /api/health` возвращает поле `environment`: `production` или `staging`.
* Новая переменная `APP_ENVIRONMENT` (по умолчанию `production`). По ней же помечаются события в Sentry.
* `AUTH_SMS_DEMO_PHONE` и `AUTH_SMS_DEMO_CODE` стали необязательными: без них приложение запускается (на тесте demo-номер не нужен). На проде они заданы, поведение не меняется.

Файлы: `HealthController.java`, `application.yml`, `application-prod.yml`, `render.yaml`, `docs/environments.md`.

## Что это значит для приложения

* На проде: в `/api/health` появилось поле `"environment": "production"`. Остальное без изменений.
* Flutter-разработчику: адрес тестового сервера для отладки — после создания сервиса (вида `https://birchat-backend-staging.onrender.com`).

## Настройка (один раз) — через Blueprint

Тестовый сервер описан кодом в [`render.yaml`](../../render.yaml) (Render Blueprint). Прод в этом файле не описан и не затрагивается.

1. Render → **New → Blueprint**.
2. Репозиторий `baglan1508/birchat-backend`, ветка **`develop`**.
3. Render покажет сервис `birchat-backend-staging` (Docker, Frankfurt, `0.5c-512mb` — $7/мес) и попросит ввести значения, которых нет в файле:
   * `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD` — бета-база Neon;
   * `AUTH_SMS_FIXED_CODE` — 4 цифры;
   * `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` — как на проде;
   * `SENTRY_DSN` — как на проде.
4. **Apply**. `AUTH_JWT_SECRET` и `AUTH_SMS_OTP_SECRET` Render сгенерирует сам.
5. По желанию: перенести сервис в «My project» → окружение Staging (кнопка Move).

Дальнейшие изменения настроек теста — правкой `render.yaml` в ветке `develop`, Render применит их сам.

## Как проверить после наката

1. Прод: `GET https://birchat-backend.onrender.com/api/health` → `"environment": "production"`.
2. Тест: в логах `Successfully applied 3 migrations ... now at version v14`, затем `Started BirchatBackendApplication`.
3. Тест: `GET /api/health` → `"environment": "staging"`.
4. Тест: вход по одинаковому коду, создание компании, сообщение в чат.

## Откат

Код: Rollback на предыдущий деплой прода (`fcd45b0`). Тестовое окружение можно просто приостановить (Suspend) на Render.
