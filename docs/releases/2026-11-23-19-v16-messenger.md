## Что изменилось

| Запрос | Кто | Что делает |
|---|---|---|
| `POST /chats/direct` `{ "userId" }` | любой сотрудник | личный чат с коллегой: существующий или новый, `200 ChatDetailsResponse` |
| `POST …/messages`, `POST …/messages/file` | участник | новые поля `replyToMessageId`, `forwardedFromMessageId` (только текстовое), `mentions` |
| `PATCH …/chats/{chatId}/messages/{messageId}` `{ "text", "mentions"? }` | автор | изменить текст (у файла — подпись) |
| `GET …/chats/{chatId}/messages/updated?since=` | участник | изменённые сообщения после `since` |

### Личные чаты (`DIRECT`)

* На пару людей в компании один чат: `chats.direct_key` = «меньший userId:больший userId», уникальный индекс. Повторный `POST /chats/direct` возвращает тот же чат.
* Себе — `400 VALIDATION`; собеседник не сотрудник — `404 USER_NOT_FOUND`.
* Видят только двое. Директор чужие личные чаты не видит нигде: список чатов, `GET /chats/{id}` (`403 CHAT_ACCESS_DENIED`), поиск, файлы, события WebSocket, пуши.
* `GET /chats`: у `DIRECT` поле `peer` (`userId`, `fullName`, `displayName`, `initials`, `avatarUrl`), `name` — `null`; чат без сообщений не показывается.
* `PATCH /chats/{id}`, добавление и удаление участников — `403 FORBIDDEN`.
* Собеседника убрали из компании: чат остаётся у второго, переписка видна, отправка — `403 CHAT_ACCESS_DENIED`.
* Файл, отправленный в личный чат, становится файлом этого чата (как у групп).
* Push: заголовок — имя автора, текст без «Имя:», без подзаголовка.

### Ответ и пересылка

* `replyToMessageId` — неудалённое сообщение этого же чата, иначе `404 MESSAGE_NOT_FOUND`. В ответе `replyTo`: `id`, `userId`, `authorName`, `text` (первые 100 символов; у вложения без подписи — имя файла), `type`, `deleted`. Исходное удалили потом — `text: null`, `deleted: true`.
* `forwardedFromMessageId` — сообщение из чата этой компании, который виден отправителю. `text` необязателен: без него берётся текст исходного. Тип сообщения — как у исходного; вложения прикрепляются те же (новые `chat_attachments` на тот же файл), и файл становится доступен в чате, куда его переслали. Пересылка пересланного указывает на первоисточник. В ответе `forwardedFrom`: `messageId`, `userId`, `authorName`.
* Миграция `V24`: `chat_messages.forwarded_from_message_id` (ответ уже был — `reply_to_message_id` из V1).

### Редактирование

* Только автор (`403 FORBIDDEN`), не позже 48 часов (`403 EDIT_EXPIRED`); пустой текст у текстового сообщения — `400 VALIDATION`; у файла подпись можно стереть.
* `editedAt` в `ChatMessageResponse`; `mentions` в запросе, если переданы, заменяют прежние.
* WebSocket `message.updated` с полным сообщением; опрос `GET …/messages/updated?since=` → `{ messages, checkedAt }` (без `since` — пустой список и серверное время, как у `deleted`).
* Push не отправляется. Поиск и AI берут текущий текст.
* Миграция `V24`: `chat_messages.edited_at`, частичный индекс `(chat_id, edited_at)`.

### Упоминания

* `mentions: [userId]` в запросе; сервер оставляет только участников чата (не автора), остальных молча отбрасывает. Текст не меняется.
* В ответе `mentions: [{ userId, fullName }]` — имя, как его видят коллеги.
* Упомянутому push приходит, даже если чат у него открыт: «Нурлан упомянул(а) вас: …» / «Нурлан сізді атап өтті: …». Остальным — обычный.
* Миграция `V24`: таблица `chat_message_mentions` (уникальная пара сообщение + человек, индекс по человеку — для будущей ленты «Меня упомянули»).

## Тесты

* `ChatServiceMessageFeaturesTest`: цитата с обрезкой до 100 символов; ответ на сообщение другого чата — `404`; пересылка копирует текст, тип и файл, проверяет доступ к исходному чату; пустой текст без пересылки — `400`; упоминаются только участники; редактирование автором, чужое — `403`, через 49 часов — `EDIT_EXPIRED`, пустой текст — `400`; `updated` без `since`.
* `ChatManagementServiceTest`: личный чат создаётся один раз и переиспользуется; себе — `400`; не сотруднику — `404`; переименовать нельзя; пустой личный чат не в списке, `peer` заполнен.
* `ChatAccessServiceTest`: директор не видит чужой личный чат; писать после ухода собеседника нельзя; пересланный файл виден в чате, куда переслали.
* `PushNotificationServiceTest`: упомянутый получает пуш с открытым чатом, на казахском; пуш личного чата — автор в заголовке.
* CI: миграции V1–V24 на PostgreSQL 18.

## Совместимость

Поля только добавлены. Старые сборки не создают личных чатов и новых полей не шлют. `text` в `POST …/messages` формально стал необязательным, но без пересылки пустой текст по-прежнему — `400 VALIDATION`.

## Откат

Rollback деплоя на Render. Колонки `V24` старой версии не мешают; но версия без этого выпуска покажет директору чужие личные чаты в списке, поэтому откат — только на время исправления.
