# Выпуск 2026-11-10-02: блокировка фоновых задач

Ветка: `feature/scheduler-lock`
Пункт плана: №2 (см. [README](README.md))

## Проблема

Сводки AI для директоров обновляются фоновой задачей раз в 3 часа (`@Scheduled`). Сейчас сервер один, и всё работает. Но как только на Render будет **два и больше** экземпляра приложения (а это первый шаг масштабирования), задача запустится на каждом:

* каждая сводка будет считаться дважды, и в два раза вырастут расходы на AI;
* в базе появятся дубли сводок.

## Что изменилось

Подключена библиотека **ShedLock 7.10.1**. Перед запуском задачи экземпляр приложения ставит блокировку в базе. Остальные экземпляры видят её и пропускают запуск.

* Новая таблица `birchat.shedlock` (миграция `V13`).
* Время блокировки берётся из базы, а не с серверов, поэтому расхождение часов не мешает.
* Параметры для обновления сводок (`aiCompanySummaryRefresh`):
  * `lockAtMostFor = 2 ч` — если сервер упадёт посреди обновления, блокировка сама снимется до следующего запуска;
  * `lockAtLeastFor = 5 мин` — защита от повторного запуска при небольшом расхождении расписаний.
* По умолчанию для будущих фоновых задач блокировка держится не дольше 30 минут.
* В задаче стоит проверка `LockAssert.assertLocked()`: если блокировку случайно отключат, задача не выполнится молча без неё.

Файлы: `pom.xml`, `SchedulerLockConfig.java`, `AiCompanySummaryScheduler.java`, `V13__create_shedlock.sql`, `AiCompanySummarySchedulerTest.java`.

## Что это значит для приложения

* API не менялся. Flutter ничего делать не нужно.
* Переменные окружения не менялись.
* Новая зависимость в `pom.xml`: при первой сборке Render скачает её, и сборка может идти на минуту дольше.
* **Миграция `V13`** создаёт таблицу, существующие данные не меняются.
