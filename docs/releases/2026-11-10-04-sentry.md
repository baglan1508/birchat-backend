# Выпуск 2026-11-10-04: мониторинг ошибок в Sentry

Ветка: `feature/sentry`
Пункт плана: №4 (см. [README](README.md))

## Проблема

Об ошибках на проде можно было узнать, только открыв логи Render. Хуже того, неожиданные ошибки (ответ `500`) перехватывал `GlobalExceptionHandler` и **не писал в лог вообще** — они терялись бесследно. Сбои фоновых задач (сводки AI, ночная чистка) были видны только в логах.

## Что изменилось

* Подключён Sentry: `sentry-spring-boot-starter-jakarta` и `sentry-logback` версии **8.63.0**.
* В Sentry уходят записи лога уровня **ERROR**:
  * неожиданные ошибки API (`500`) — теперь они ещё и пишутся в лог;
  * ошибки API с кодом `5xx` (недоступен Supabase, AI, Telegram Gateway);
  * сбои фоновых задач: обновление сводок AI, ночная чистка.
* Записи уровня INFO и WARN прикладываются к событию как «хлебные крошки» — видно, что происходило перед ошибкой.
* Ошибки `4xx` (неверный код, нет доступа, валидация) в Sentry **не отправляются** — это ожидаемое поведение, а не сбои.
* К событию прикладывается только `id` пользователя. Телефон, имя, тело запроса, заголовок `Authorization` и cookies **не отправляются** (`send-default-pii: false`, `max-request-body-size: none`).
* Трассировка производительности выключена (`traces-sample-rate: 0`), чтобы не тратить бесплатную квоту Sentry.
* Пока `SENTRY_DSN` не задан, Sentry **выключен**, поэтому накат безопасен и до настройки.

Файлы: `pom.xml`, `application.yml`, `GlobalExceptionHandler.java`, `CurrentUserArgumentResolver.java`.

## Что это значит для приложения

* API не менялся. Flutter ничего делать не нужно.

## Настройка (один раз)

1. Зарегистрироваться на [sentry.io](https://sentry.io) (бесплатный тариф Developer).
2. **Create Project** → платформа **Spring Boot** → имя `birchat-backend`.
3. Скопировать **DSN** — строку вида `https://…@….ingest.sentry.io/…` (Settings → Client Keys (DSN)).
4. На Render → **Environment** добавить:

| Переменная | Значение |
|---|---|
| `SENTRY_DSN` | DSN из шага 3 |
| `SENTRY_ENVIRONMENT` | `production` (необязательно, это значение по умолчанию) |

5. Оповещения: по умолчанию Sentry присылает письмо на почту аккаунта о каждой **новой** ошибке. Настраивается в **Alerts**.

Версия кода в событиях берётся из переменной Render `RENDER_GIT_COMMIT` автоматически.

## Как проверить после наката

1. В логах Render: `Started BirchatBackendApplication`, без ошибок.
2. После добавления `SENTRY_DSN` и перезапуска в логах при старте нет предупреждений Sentry про DSN.
3. Ошибка попадёт в Sentry при первом реальном сбое. Для проверки можно запросить подписанную ссылку на файл, если временно отключить Supabase, но на проде так делать не нужно — достаточно дождаться первого события.

## Откат

Удалить `SENTRY_DSN` на Render — Sentry выключится без отката кода. Полный откат — Rollback на предыдущий деплой (`106e0c8`).
